关键能力①：11 个自研业务工具

工具功能科学依据
evaluate_training负荷估算 + 三档评估 + 恢复时长负荷=时长×min(1,max(.1,(HR−60)/140))
plan_next_workout下一次互补训练规划12 类运动互补映射；负荷≥80 强制恢复
compute_fatigue7 天疲劳指数 0–100权重 [7..1] 加权 / 350 归一化
plan_daily_diet每日热量 + 双碳水 + 饮水Mifflin-St Jeor BMR×活动系数
recovery_meal_plan运动后恢复餐配比蛋白30/碳水50/脂肪20；超标×0.6
estimate_one_rep_max1RM 极限重量估算Epley + Brzycki 双公式交叉
effective_sets有效组数/容量RPE 或 10−RIR ≥ 7 计入
what_if_simulate4/8 周体重与负荷推算7700 kcal ≈ 1kg 经验公式
generate_image文生图：训练动作示意图百炼文生图模型，异步任务 API，落盘 output/images/
read_skill / write_weekly_reportSkill 读取 / 周报写入白名单 + 文件名清洗（权限隔离）

关键能力②：一句话 → 多工具 · Skill → 产出物

🗣️ 「我今天练了 90 分钟力量，心率 125，消耗 500 千卡，帮我评估、安排明天的训练、再告诉我怎么吃」

① evaluate_training

负荷 47 → 偏低 → 恢复 8h

② plan_next_workout

力量 → 有氧慢跑+拉伸 25min

③ recovery_meal_plan

蛋白 38g / 碳水 63g / 脂肪 11g

📘 Skill 演示：说「帮我生成周训练报告」→ Agent 调 read_skill("weekly-report") 读取 SKILL.md → 按模板调 compute_fatigue 等计算 → 展示全文征得同意后才调 write_weekly_report 写入 output/周训练报告_*.md

⚠️ 写文件是唯一"危险操作"：先确认、后写入；且只能写 output/（路径逃逸被单元测试拦截）

可演示性：执行过程面板（工具真被调用）

⚙️ 执行过程（本轮 3 次工具调用）

→ 调用工具 evaluate_training
  {"sport_type": "力量", "duration_min": 90, "avg_heart_rate": 125}

✅ 返回 {"load": 47, "load_status": "偏低", "suggested_recovery_hours": 8, ...}

→ 调用工具 plan_next_workout
  {"sport_type": "力量", "training_load": 47}

✅ 返回 {"workout_type": "有氧慢跑 + 全身拉伸", "duration_min": 25, ...}

→ 调用工具 recovery_meal_plan …

界面内置面板逐条展示每次工具的名称 / 入参 / 返回（✅/❌）；工具异常时返回可读 error，Agent 会向用户解释原因而非崩溃。

侧边栏：当前模型与端点、11 个已注册工具清单、会话保存/加载（sessions/*.json）。

思政与合规说明

🏥 健康边界

饮食建议由工具与系统提示词强制附带「日常营养参考，非医疗诊断；如有基础疾病请遵医嘱」；伤病只建议休息与就医

🔒 隐私保护

不采集真实个人信息；周报用 SKILL.md 声明的虚构样例；会话仅存本地

🛡️ 权限隔离

Agent 只能写 output/ 目录：白名单 + 文件名清洗防路径逃逸，pytest 验证（test_write_sandbox）

📚 学术诚信

算法来自本人另一独立项目，已在 README 说明；课堂 demo 仅作能力基线；仓库无任何真实密钥
